
## Step 3 — Production env vars

Append to `/var/proyectos/tote-web/backend/.env` (or your secret manager):
```
REDIS_URL=redis://localhost:6379
REDIS_ENABLED=true
SNAPSHOT_WORKERS_ENABLED=true
REPORT_USE_MATERIALIZED=true
```

## Step 4 — Restart backend, confirm registration

```bash
ssh 94 "pm2 restart tote-backend"
ssh 94 "pm2 logs tote-backend --lines 200 --nostream | grep -E '(redis|Workers|pg-boss)'"
```
Expected log lines (in order):
- `[redis] connected`
- `[pg-boss] Workers refresh-live-snapshots + refresh-daily-snapshot registrados (cron 1/min)`

If `[redis] connected` is absent but the worker line is present: cache is
disabled but workers still run — investigate the Redis container before
proceeding.

## Step 5 — Cron registration

Append to `/etc/cron.d/tote-triggers`:
```cron
# v1.4 perf — live snapshot refresh, every minute
* * * * * root /usr/bin/node /var/proyectos/tote-web/backend/src/scripts/trigger-pgboss-cron.mjs refresh-live-snapshots

# v1.4 perf — daily aggregate refresh, every minute
* * * * * root /usr/bin/node /var/proyectos/tote-web/backend/src/scripts/trigger-pgboss-cron.mjs refresh-daily-snapshot
```

Verify the allowlist already accepts these queue names:
```bash
ssh 94 "grep -E 'refresh-(live-snapshots|daily-snapshot)' /var/proyectos/tote-web/backend/src/scripts/trigger-pgboss-cron.mjs"
```
Expected: both lines present.

## Step 8 — Watch for 24h

```bash
ssh 94 "pm2 logs tote-backend --lines 500 --nostream | grep -E '\[cache\]|\[refresh-(live|daily)\]'"
```
Watch for:
- `[cache] get failed ... — falling back` should be rare (< few/hour). High rate ⇒ Redis intermittent.
- `[refresh-live-snapshots] SLOW: ...ms` ⇒ worker approaching the 30s budget.
- `processed=N failed=M` ⇒ M should be 0 in steady state.

## Rollback levers (in order of severity)

1. **`REDIS_ENABLED=false`** + `pm2 restart tote-backend`. Cache bypassed; code unchanged; behavior reverts to direct DB reads. Zero data loss.
2. **`SNAPSHOT_WORKERS_ENABLED=false`** + restart. Cron still fires, workers no-op. Snapshot tables stop growing but read paths still work.
3. **Comment out the two cron lines** in `/etc/cron.d/tote-triggers`. Workers stop receiving jobs.
4. **`git revert` the v1.4 commits** + `pm2 restart`. Tables remain (additive, no harm).

## Known interactions with v1.3 (joint deploy)

- v1.4 invalidation hook lives inside `calculate-draw-financials.worker.js`
  (Phase 11). It is wrapped in try/catch — a Redis failure does NOT roll
  back the DrawFinancial write.
- `REPORT_USE_MATERIALIZED` default flips from `false` → `true`. Production
  must set it explicitly in `.env` to retain control if rollback is needed.
- The `DrawLiveSnapshot` and `DailyAggregateSnapshot` migrations are purely
  aditive (CREATE TABLE + CREATE INDEX + ADD FK). No existing table is
  altered. Safe to roll forward on top of the v1.3 migration set.
