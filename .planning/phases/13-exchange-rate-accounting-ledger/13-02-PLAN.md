<objective>
Build the backend business-logic and request-handling layer for Phase 13: three service modules (exchange-rate, accounting-entry, category) wrapped by three controller classes. Services enforce F-4 (decimal.js precision), F-6 (no USD entry without rate), F-7 (locked exchangeRateId at create), FIN-LEDGER-09 (immutable monetary fields), D-01 (last-loaded-of-day rate lookup), D-02 (category soft-delete), D-03 (PAYMENT→settlement guard), and D-06 (atomic reversal). Controllers wrap each mutation in an AuditLog row that always includes ipAddress + userAgent (P-4 corrects the omission in the existing admin-jobs.controller.js pattern).

Purpose: Plan 13-03 mounts these controllers into a router and adds the attachment + static-storage-guard pieces. Plan 13-04 (UI) consumes the route surface. By keeping route wiring out of this plan, the service+controller layer is unit-testable without HTTP-framework concerns, and the 13-03 router file becomes a small composition step.

Output: 3 service modules + 3 controller classes, all using singleton prisma, all writing AuditLog rows with the full diagnostic triple (userId+ipAddress+userAgent), all enforcing immutability rules at the application layer, no UPDATE endpoint for rates.
</objective>
