**Step 1 — Update schema.prisma Ticket model:**

Open `backend/prisma/schema.prisma`. Find the Ticket model (around line 944). The current index block at the bottom of the model looks like:

```prisma
  @@index([drawId])
  @@index([status])
  @@index([source])
  @@index([externalTicketId])
  @@index([userId, status])
  @@index([drawId, source])
  @@index([createdAt])
```

Add the following line immediately AFTER the existing `@@index([externalTicketId])` line and BEFORE `@@index([userId, status])`:

```prisma
  @@unique([drawId, externalTicketId, source])
```

The constraint is scoped to `source` so that the same `externalTicketId` can exist across different sources (e.g., SRQ `EXTERNAL_API` and a future `WEBHOOK_PUSH` provider during onboarding coexistence). It blocks true duplicates within a single source.

**Step 2 — Run db push locally:**


This must complete with no errors. The existing SRQ row data will not conflict because existing `EXTERNAL_API` tickets either have unique (drawId, externalTicketId) pairs or null `externalTicketId` values — and null values are excluded from unique constraint enforcement in PostgreSQL. If `db push` reports a conflict, investigate the existing data before proceeding.
